# 1. Objective

Establish and maintain the first intentional shared contract foundation for the JavaScript Notebook repository.

This sub-stage builds on the verified shared module/build boundary established in 2.2.7.1 and reflects the repository's current state: a shared application contract is already in use by both the frontend and backend, with successful build and type-check verification.

The objective is to define and maintain only shared contracts justified by the current application architecture while preserving:

```text
frontend → shared
backend  → shared

shared ↛ frontend
shared ↛ backend
```

The shared layer must remain a single source of truth and must not become a premature notebook-domain model.

---

# 3. Current Shared Contract

The repository currently has one initial shared contract:

```text
shared/src/application.ts
```

It provides:

```text
ApplicationState
application
```

The current shape is:

```ts
export type ApplicationState = {
  title: string;
  version: string;
};

export const application: ApplicationState = {
  title: "JavaScript Notepad",
  version: "0.1.0",
};
```

This small contract is sufficient to establish the initial shared-code pattern.

---

# 4. Contract Ownership

A contract belongs in `shared/` when both application sides require the same definition.

The intended relationship is:

```text
shared contract
      │
      ├── frontend consumption
      └── backend consumption
```

The frontend or backend must not maintain a duplicate definition of the same shared contract.

---

# 5. Single Source of Truth

The implementation must maintain one authoritative definition.

Do not create parallel copies such as:

```text
frontend/src/application.ts
backend/src/application.ts
shared/src/application.ts
```

when they represent the same contract.

The intended source of truth remains:

```text
shared/src/application.ts
```

---

# 6. Shared Contract Principles

Shared contracts should be:

- Explicit
- Small
- Stable
- Intentionally reusable
- Independent of frontend implementation
- Independent of backend implementation
- Compatible with both TypeScript environments

A shared contract describes a common structure, not application-specific runtime behavior.

---

# 7. Runtime Independence

Shared source must not depend on:

```text
React
React DOM
Vite
Browser DOM APIs
Node.js HTTP APIs
Node.js filesystem APIs
Backend server modules
Frontend components
```

The shared layer should remain portable.

---

# 8. Dependency Direction

The permitted dependency graph remains:

```text
frontend ──────┐
               ▼
             shared
               ▲
               │
backend ───────┘
```

Valid:

```text
frontend → shared
backend  → shared
```

Invalid:

```text
shared → frontend
shared → backend
```

No circular dependency may be introduced.
